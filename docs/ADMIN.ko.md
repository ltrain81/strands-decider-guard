# 정책 관리 콘솔 사용법

[English](ADMIN.md)

개발자가 아니어도 웹 화면에서 무엇을 막을지 정할 수 있습니다. 저장하면 **30초 안에** 모든 코딩 에이전트에 적용됩니다.
Claude Code, Kiro, Codex hook 과 LiteLLM 프록시에 모두 적용되며, 재배포는 필요 없습니다.

## 접속

- 주소: `make console` 로 확인합니다. 배포가 끝날 때도 출력됩니다.
- 계정 만들기: `make add-admin ADMIN_EMAIL=이메일`. 임시 비밀번호가 메일로 오고, 처음 로그인할 때 새 비밀번호를 정합니다.
  - 배포하면서 바로 만들려면 `make deploy ... ADMIN_EMAIL=이메일`.
  - 콘솔 계정과 개발자 PC 의 AWS 권한은 별개입니다. 콘솔에 로그인할 수 있는 사람만 정책을 바꿀 수 있습니다.
- AWS 없이 내 PC 에서 써 보려면 `make local-console` 을 실행합니다(로그인 없음, 127.0.0.1 전용).
  - 여기서 저장한 정책은 `~/.decider-guard/policy.json` 에 저장됩니다.
  - 로컬 모드 hook(`make local`)이 이 파일을 바로 읽습니다.
- 언어: 화면 위쪽의 **EN / 한국어** 버튼으로 바꿉니다. 기본은 브라우저 언어를 따르고, 링크에 `?lang=ko` 를 붙이면 한국어로 열립니다.

## 개요 탭

첫 화면에서 guard 가 잘 동작하는지, 무엇을 하고 있는지를 봅니다.

- **상태:**
  - Guard: 모델에 닿는지, 어떤 모델과 디바이스인지
  - GPU 호스트: 실행 중인지, 정지됐는지
  - 정책: 언제, 누가 마지막으로 저장했는지
  - 알림: 켜진 규칙 수와 경보 중인 규칙
- **기간별 숫자** (1시간~30일): 전체 검사, 차단·확인 건수와 비율, p95 지연, guard 오류
- **차트:**
  - 시간대별 판정 (허용 / 확인 / 차단)
  - 지연시간 (중앙값, p95)
  - 차트에 마우스를 올리면 시간대별 값이 보입니다.
- **분석:** 정보 유형이나 회사 규칙별 차단 사유, 도구별 검사 수
- **최근 차단·확인** 목록과 전체 로그로 가는 링크. "자동 새로고침"을 켜면 1분마다 다시 불러옵니다.

## 정책 탭

### 기본 민감도
| 선택 | 이럴 때 | 벤치마크 (검증용 절반): 재현율 · 오탐 · 개발 텍스트 오탐 |
|---|---|---|
| 관대 | 오탐 때문에 업무가 막히는 게 더 큰 문제일 때 | 63% · 1.4% · 0% |
| **보통 (권장)** | 대부분의 경우 | 70% · 3.4% · 3.1% |
| 엄격 | 금융·의료처럼 놓치면 안 될 때 | 76% · 4.7% · 6.2% |

### 정보 유형별 동작
각 유형마다 **차단 / 확인 / 허용** 중 하나를 고릅니다.
- **차단**: 에이전트가 그 내용을 읽거나 쓰거나 모델에 보내지 못합니다.
- **확인**: Claude Code 는 사용자에게 "계속할까요?" 를 묻습니다. 사용자 확인을 지원하지 않는 Kiro, Codex, LiteLLM 은 차단합니다.
- **허용**: 그 유형은 검사하지 않습니다.

**인사·법률·사생활** 유형은 특정인의 징계·인사, 소송, 범죄 경력, 체류 자격, 종교·정치 성향, 노조 가입, 성적 지향, 가족 사정을 다룹니다.
대부분의 개인정보 법령이 민감정보로 보는 내용이고, 정규식으로는 찾을 수 없습니다.

"주민·외국인등록번호"는 번호 형식으로 찾습니다. AI 모델의 신분증 판단은 "신분증 번호" 설정을 따르므로, 둘을 같이 바꾸는 것이 자연스럽습니다.

### 우리 회사만의 규칙
막고 싶은 내용을 **예/아니오로 답할 수 있는 질문**으로 적습니다. 정규식이나 키워드 목록이 아니라, AI 모델이 매번 이 질문으로 판단합니다.

좋은 질문의 예:
- 사내 프로젝트 'Phoenix(피닉스)'의 미공개 일정, 매출, 출시 계획이 포함되어 있나요?
- 직원의 급여, 연봉, 인사 평가 정보가 포함되어 있나요?
- 고객사와의 계약 금액이나 계약 조건이 포함되어 있나요?

잘 쓰는 법:
- **한 질문에 한 주제**를 다룹니다. 여러 주제를 섞으면 판단이 흐려집니다.
- **다른 표기도 함께** 적습니다. 예: `Phoenix(피닉스)`. 한글 표기만 쓴 문장을 놓친 경우가 있었습니다.
- 막고 싶은 것을 **구체적으로** 씁니다. "회사 기밀이 있나요?" 보다 "미공개 출시 일정이 있나요?" 가 정확합니다.
- 규칙마다 따로 민감도를 줄 수 있습니다. 놓치면 안 되는 규칙은 "엄격" 으로 둡니다.
- 저장 전에 **테스트 탭**에서 막혀야 할 문장과 통과해야 할 문장을 하나씩 넣어 봅니다.

규칙은 최대 20개입니다. 규칙이 늘어도 검사 시간은 크게 늘지 않습니다. 같은 텍스트에 질문만 추가되기 때문입니다.

### 예외 (허용 목록)
- **이메일 도메인**: 회사 도메인을 넣으면 그 도메인 주소는 검사 전에 지워집니다.
- **무시할 단어**: 테스트용 가짜 이름(`홍길동`), 대표번호 같은 값을 넣습니다.

예외 값은 텍스트에서 지워진 뒤에 검사됩니다. 예를 들어 `홍길동` 을 예외로 넣으면 "홍길동 환자는 우울증 치료 중" 문장은 **특정인이 없는 문장**이 되어 통과합니다. 실제 사람 이름은 넣지 마세요.

### 차단 안내 문구
차단될 때 개발자에게 보이는 문구입니다. 문의 채널을 적어 두면 좋습니다.

### 저장
화면 아래에 "저장하지 않은 변경이 있습니다" 가 뜨면 **저장하고 적용**을 누릅니다. **되돌리기**는 마지막 저장 상태로 돌아갑니다.

## 테스트 탭
- 문장을 넣고 **검사하기**를 누르면 **저장하지 않은 현재 설정**으로 판정합니다.
- 결과는 차단 / 확인 필요 / 허용 중 하나이고, 이유가 함께 나옵니다. 예: "건강·의료 정보 (AI 판단: 민감 정보 97%, 특정인 65%)".
- 테스트한 문장은 기록되지 않고 통계에도 들어가지 않습니다.

## 로그 탭

- **판정 로그:** guard 가 한 모든 검사입니다.
  - 기간, 판정, 도구, 정보 유형(또는 회사 규칙), 대상(파일 이름, `prompt`, `bash` 등)으로 걸러 봅니다.
  - 행을 누르면 상세가 보입니다. CloudWatch 에서 찾을 때 쓰는 요청 ID 도 있습니다.
  - **CSV 내보내기**로 화면의 결과를 내려받습니다.
  - **원문은 어디에도 저장되지 않습니다.** 판정, 도구, 대상, 유형, 크기, 지연시간만 남습니다.
- **관리자 활동:** 누가 정책을 저장하거나 알림을 바꿨는지, 무엇이 바뀌었는지 보여 줍니다. 예: "민감도: 보통 → 엄격", "규칙 추가: 프로젝트 Atlas".
- AWS 에서는 CloudWatch Logs 를 조회하므로 긴 기간은 몇 초 걸릴 수 있습니다.

## 알림 탭

AWS 배포에서만 동작합니다. guard 에 문제가 생기면 메일로 알려 줍니다.

- **수신자:**
  - 이메일 주소를 추가합니다. 새 주소에는 AWS 가 확인 메일을 보내고, "Confirm subscription" 을 눌러야 알림을 받습니다.
  - 그 전까지 상태는 *확인 대기 중* 입니다.
- **규칙:** 각각 켜고 끌 수 있고, 지금 상태(정상 / 경보 / 데이터 대기)가 보입니다.

| 규칙 | 울리는 조건 | 기본값 |
|---|---|---|
| Guard 다운 | 5분마다 하는 상태 점검이 10분 동안 모델에 닿지 못함 | 켜짐 |
| Guard 오류 | guard Lambda 가 오류를 냄 | 켜짐 |
| 차단 급증 | 5분 동안 차단이 *N* 건 초과 | 꺼짐, N = 20 |
| 검사 지연 | 10분 동안 p95 지연이 *N* ms 초과 | 꺼짐, N = 3000 |

- **테스트 알림 보내기**로 메일이 도착하는지 확인합니다.
- GPU 호스트를 정지하면(`make stop`) *Guard 다운* 이 울립니다. 일부러 정지할 때는 그 규칙을 먼저 끄세요.

## 변경 이력 탭
- 저장할 때마다 버전이 남고, 누가 언제 저장했는지 보입니다.
- **비교**를 누르면 그 버전을 불러올 때 무엇이 바뀌는지 보여 줍니다.
- **불러오기** → 정책 탭에서 내용 확인 → **저장하고 적용** 순서로 예전 설정으로 되돌립니다.

## 알아 둘 점
- 정책은 각 판정 요청에서 읽고 30초 캐시합니다. 저장 직후 30초 동안은 이전 정책이 적용될 수 있습니다.
- 정책 파일을 읽지 못하면 guard 는 **마지막으로 읽은 정책을 계속 적용**합니다. 정책이 없으면 기본값(전부 차단, 보통)을 씁니다.
- 판정 품질은 합성 샘플 수십 개로만 확인했습니다. 실제 업무 문장으로 테스트 탭에서 꼭 확인하세요.
